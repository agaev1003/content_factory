# Предложение первой версии

Статус: проектирование. Приложенный макет демонстрирует действия в браузере и не подключён к социальным сетям.

## Сценарий пользователя

1. Скилл монтажа выдаёт готовый MP4. При наличии рядом лежат обложка, сценарий и текст описания.
2. Пользователь перетаскивает пачку роликов в подборку: например, «Уроки», «Вопросы», «Эфиры».
3. В карточке — видео, название и три подписи. Общий текст можно скопировать на все площадки и затем поправить отдельно. У YouTube есть отдельный заголовок.
4. Правило задаёт дни и время; материалы по очереди занимают свободные места.
5. До запуска видны ближайшие публикации и дата, до которой хватает запаса.
6. После отправки видны независимые состояния Instagram, TikTok и YouTube, ошибки и ссылки на опубликованные ролики.

## Фаза → предложение

| Элемент | В Фазе | Предлагаем для личного кабинета |
| --- | --- | --- |
| Навигация | Подключение, файлы, правила, календарь, охваты, подписчики | Ролики, расписание, подключения; результат рядом с каждым роликом |
| Форматы | Четыре категории контента | Одна категория: готовое вертикальное видео |
| Площадки | Восемь сетей | Instagram Reels, TikTok, YouTube Shorts |
| Подписи | Общая подготовка публикации | Общая основа и отдельная версия на площадку |
| Очередь | Порядковые номера и правила папок | Наглядный порядок и ближайшая дата напротив ролика |
| Контроль | Календарь и отдельная аналитика | Три состояния в строке ролика; ошибка одной сети не скрывает успех другой |
| Массовая загрузка | Автор в уроке предупреждает о прерывании при переходах | Загрузка живёт независимо от открытого раздела; каждый файл имеет прогресс и повтор |
| Монтаж | Отдельная задача по словам автора | Готовый результат существующего скилла без встроенного редактора |

## Архитектура без привязки к одному сервису

```text
Скилл монтажа
    ↓ MP4 + обложка + сценарий (если есть)
Собственный кабинет → собственный архив оригиналов
    ↓ проверенные подписи и план
Исполнитель публикаций (первым проверить Postiz)
    ↓ независимая задача на каждую площадку
Instagram / TikTok / YouTube
    ↓ статус, ID, ссылка, ошибка
Собственный журнал результатов
```

Для собственной небольшой серверной части достаточно одной базы и файлового хранилища. Если использовать готовый планировщик, не создавать второй конкурирующий механизм времени: кабинет передаёт план исполнителю, сохраняет его ID и следит за результатом. Предварительное заполнение свободных мест в кабинете — это расчёт, не запуск публикации.

## Данные и правила надёжности

- **Материал:** ID, контрольная сумма файла, подборка, порядок, оригинал MP4, обложка, доступные технические характеристики. Проверка формата не меняет видео.
- **Версия площадки:** подпись, заголовок YouTube, параметры видимости и другие действительно поддержанные выбранным подключением поля.
- **План:** материал + аккаунт + площадка + дата UTC + отображаемый часовой пояс. По умолчанию Europe/Moscow. Не хранить время только строкой «19:00».
- **Отправка:** внутренний ID операции, ID у исполнителя, время запроса, последний ответ, число попыток, подтверждённая ссылка, причина ошибки.
- Черновик, готов к проверке, запланировано у исполнителя, обрабатывается, опубликовано, требуется действие, ошибка — разные состояния.
- HTTP 200 или наличие задачи в очереди не означают публикацию. Подтверждение — результат обработки и ID материала у площадки; при отсутствии ссылки показать, что она ещё не получена.
- При таймауте после отправки сначала выяснять состояние прежней операции. Не отправлять тот же ролик заново вслепую.
- Если время прошло при остановленном сервисе, требовать явного решения: пропустить, перенести или отправить сейчас. Не выпускать весь накопленный хвост разом.
- Остановка правила должна учитывать задачи, уже переданные исполнителю. Локальный переключатель сам по себе не отменяет чужое расписание.
- Подписи проходят проверку длины и обязательных полей выбранного подключения. Возможность публикации с отдельной обложкой и наличие статистики проверяются по площадке.
- Оригинал хранится независимо от копии у исполнителя. Метаданные и медиа входят в резервные копии.
- Секреты — только на сервере, вне Git и браузерного кода. Для работы с трёх площадок не нужны пароли или cookies в публичном репозитории.

## Как испытать до большого строительства

Проверить подключение всех трёх реальных аккаунтов, один немедленный и один отложенный тест согласованного материала. Убедиться, что после закрытия браузера отправка продолжается; проверить отдельный отказ одной площадки, истёкшее подключение и повтор после таймаута без дубля. После перезапуска должны сохраняться очередь, подписи и ссылки.

Без этих проверок состояние проекта называется «макет / интеграция в разработке», а не «готовый контент-завод».

## Что намеренно откладываем

Генерацию видео, нарезку, озвучку, субтитры и монтаж; тексты и карусели для дополнительных сетей; многопользовательский сервис; сложную аналитику; автоматическое повторное размещение старых роликов. Возможности вроде пробных Reels и музыки добавляются только после отдельного теста доступности.
